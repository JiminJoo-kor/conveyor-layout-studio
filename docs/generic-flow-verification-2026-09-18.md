# 범용 연결·시퀀스·핸드셰이크 보완 결과

2026-09-18 / 기준 c362c16 이후 로컬 변경. 커밋·푸시·운영 배포 미실시.

## 판정

특정 DXF 출처·프로젝트 이름에 의존하던 실행 경로와 주요 인계/재고/화면 불일치를 보완했다. 새 JSON 프로젝트, 두 창고 병렬·직렬 구성, 분기·재합류 구성으로 검증했다. **모든 사용자 저장 프로젝트나 모든 가능한 배치의 무교착·물리 안전을 검증한 것은 아니다.** 아래 미완료 범위까지 포함해 “완전한 범용 엔진”으로 승인하면 안 된다.

## 적용한 공통 계약

1. 설비 ID와 방향 연결점으로 경로를 읽는다. 없는 설비, 중복 연결, 잘못된 AS/RS 입출고 포트, 유효하지 않은 운전값은 실행 전에 거부한다. ProcessLine은 실행 설비가 아닌 주석이다.
2. 상류 출구 요청 → 하류 가동/점유/안전간격/예약 확인 → 병렬 요청 우선순위 → 인계 완료 → 소유권 이전 순서로 처리한다. 이전에 일부 설비가 이 절차를 건너뛰던 경로를 제거했다.
3. 일반 단일 적재 설비는 사용 중·고장 중 추가 진입을 차단한다. 컨베이어는 실제 길이, 진행축에 투영한 물류 길이, 안전간격과 연속 인계 설정을 사용한다. Buffer는 설정 용량을 사용한다.
4. 목적지 연결이 없는 비종단 설비는 물류를 삭제하지 않고 출구 대기 및 진단 사유를 남긴다.
5. 연결선 길이는 인계 시간/UPH에 포함하지 않는다. AGV·AMR 자체 운반 시간은 해당 장치의 이동거리/속도 설정으로 계산한다.

## 실제 수정

- AS/RS: `state.warehouses[equipmentId]`로 창고별 재고, 셀 예약, 스태커, 모드, 3D LIVE 분리. 기존 `state.asrs`는 첫 창고 호환 별칭만 유지.
- AS/RS 입고: `product-N-in`이 저장 구역을 결정하고 물류 종류·색·입고 방향은 유지. 서로 다른 스태커도 같은 빈 셀을 중복 예약할 수 없음.
- AS/RS 출고: 빈 셀에서 가상 물류를 생성하지 않음. 다음 설비 인계 완료까지 재고와 소유권을 유지. 인계 중 고장·수용 불가 시 타이머를 동결하고 같은 시각의 반복 검사로 시간이 중복 차감되지 않게 함.
- 두 AS/RS 직렬 연결: 수신 창고 정보가 송신 창고의 셀·구역을 덮어쓰지 않도록 송신 기록 분리. 인계 타이머가 반복 초기화되어 영구 정지하던 현상 수정.
- 포킹: 포크 비율 70%는 기존 경로 3개 + 포크 7개라는 의미로 통일. 경로 미리보기는 계수하지 않고 실제 인수 시 계수.
- 동역학/시퀀스: 포킹 단계 시간에 가감속 반영, 로봇 PICK/PLACE와 Sink 배출 시간 적용, 모바일 주행속도의 레거시 `speed` 우선 적용 오류 수정.
- 방향/간격: 컨베이어 점유·수용량·초기 위치·이동 목표에 물류 방향 투영 적용. 화면 끝단으로 도형 중심을 강제로 되돌리는 보정 제거. 실제 위치를 그린 후 설비 경계로 클리핑.
- 표시 비율: 각 컨베이어 물리 길이에 맞는 비례 스케일 사용. 인계 중 양쪽 도형에 하나의 보간 스케일과 동일 종횡비 적용.
- 모바일: 운행 좌표를 회전 배치점 기준으로 다시 돌리던 오류 수정. 작업별 선택 입출력 경로를 운반·인계·복귀에 유지.
- 파라미터: 동작하지 않는 H/P 버퍼 수, 작업자 수, 디버터 분기 수는 UI에서 제외. 공통 적용은 같은 타입/역할의 운전값만 복사하며 Dock 역할·라인·물류 정체성·연결은 보존.
- 신규 입고 Dock 추가가 기존 모든 창고의 스태커 수를 자동 증가시키지 않음. 필요한 창고의 물품 구분 수는 해당 창고에서 설정. 레거시 자동 확장이 필요한 데이터만 `autoExpandProductTypes=1`로 명시 가능.
- 표시/집계: 창고별 2D/3D 셀 위치와 저장 구역 표시 보완. UPH는 셀 적재 완료/출고 인계 완료로 계수. 여러 스태커의 합산 작업시간은 전체 스태커 수로 정규화.
- 진단: 설비별 요청 의도, 차단 이유, 물류 번호, 출입 연결점, 예약 및 점유를 TXT에 포함. 리포트도 DXF 전용 필터/고정 공정 설명 대신 실제 연결점 목록 사용. 명목 시간과 실제 완료 CT를 구분.

## 남은 범위 — 완전 범용으로 승인하기 전 필요

1. **실제 프로젝트 재생 검증**: 현재 작업 공간에는 사용자 저장 프로젝트 JSON 전체가 없다. 프로젝트별 JSON과 현상 재현 시점으로 포트 방향·닫힌 순환·병목/장기 교착을 추가 확인해야 한다.
2. **차량 관제**: 개별 설비 인계 예약과 다차량 공유 통로/교차로 예약은 다르다. AMR·AGV 상호 회피, 장애물/실측 설비 간섭, 교차로 데드락 방지 관제는 아직 구현되지 않았다.
3. **속도 프로파일 정밀 통합**: 컨베이어 고정 dt/Jerk 적분과 예상 그래프의 해석식, 모바일/ASRS 단계별 프로파일은 아직 완전히 단일화되지 않았다. 그래프가 실제 Jerk 곡선/모든 대기 포함 CT와 정확히 같다고 보면 안 된다. AS/RS 상승·하강 속도의 실제 방향별 왕복 분리도 후속 보완 대상이다.
4. **DXF 자동 추론**: 기존 도면의 트림/화이날/도어 이름 기반 자동 장치 삽입 규칙은 남아 있다. 수동/JSON 실행은 연결 그래프를 사용하지만 DXF 자동 구성의 업종 독립성까지 완료된 것은 아니다.
5. **혼재 화물**: 물류 종류/색은 개별 유지하지만 길이·폭·무게는 프로젝트 공통 규격이다. 종류마다 다른 규격·하중을 동시에 쓰려면 별도 화물 모델이 필요하다.
6. **실행 중 구조 변경**: 스태커 수/셀 구조 등은 초기화 대상이다. timed 설비 운전값 변경은 진행률을 보존하나, 모든 축의 현재 속도·가속도를 보존하는 재계획은 아직 아니다. 일반 속도값 0은 실행 검증 오류이며 정지 명령으로 사용하지 않는다.
7. **계량/규모**: 같은 표시 이름의 라인 UPH는 현재 이름 기준 합산이다. 프로젝트/라인 고유 ID별 완전 분리, 수천 설비 대규모 성능, 실제 현장 측정 CT 대조는 별도 검증이 필요하다.

이는 물류 흐름 시뮬레이터의 논리 검증이다. 실제 PLC 안전회로나 기계 안전 인증을 대체하지 않는다.
