# Conveyor Layout Studio

기존 단일 HTML 컨베이어 시뮬레이터를 기준본으로 삼아 고도화하는 새 프로젝트입니다.

## 2차 범위

- 숫자 입력값과 A/B 트레이 선택 검증
- A/B가 동시에 투입 대기 중일 때 교대 우선순위 적용
- 로봇·스테이션·지게차 가동시간 누적
- 처리량, 로봇 가동률, WIP, 추정 병목 KPI 표시
- 1번/2번 컨베이어 상태 표시 보완
- 900px 이하 반응형 레이아웃
- 시뮬레이션 엔진, Canvas 렌더러, 앱 제어 모듈 분리
- 설비·노드·연결 관계를 표현하는 버전형 레이아웃 JSON
- JSON 불러오기 및 저장
- JSON 좌표와 노드를 기반으로 레이아웃 자동 렌더링
- 레이아웃 참조 무결성 및 시뮬레이션 자동 테스트

## 3차 편집기 기반

- 도면 이미지를 Canvas 배경으로 업로드
- 휠 확대·축소와 Shift+드래그 화면 이동
- 로봇·스테이션·지게차 설비 객체 추가
- 설비 선택, 10px 그리드 드래그, 이름·좌표 수정
- 사용자가 추가한 설비 삭제
- 배경 이미지와 편집 결과를 레이아웃 JSON으로 저장 및 복원

기존 공정을 구성하는 핵심 설비는 시뮬레이션 무결성을 위해 편집기에서 삭제되지 않습니다. 사용자가 추가한 `*-custom-*` 설비만 삭제할 수 있습니다.

## 4차 DWG 분석 기반

- DWG/DXF 업로드 UI와 Vercel CAD 분석 프록시
- 레이어명, 블록명, 문자와 속성을 이용한 설비 분류
- 컨베이어, 디버터, 셔틀, AGV, AMR, 소터, 리프트, 자동창고, 로봇, 작업대, 버퍼, 도크 분류 규칙
- 형상 크기와 DWG 속성에서 기본 파라미터 추론
- 인식 신뢰도와 `candidate` 검수 상태 저장
- CAD 좌표를 Canvas 좌표로 변환해 레이아웃 설비 객체 생성

네이티브 DWG 해석은 브라우저에서 직접 수행하지 않습니다. Vercel 환경 변수 `CAD_ANALYZER_URL`에 Autodesk APS 또는 ODA 기반 분석 서비스를 연결해야 하며, 필요한 경우 `CAD_ANALYZER_TOKEN`을 함께 설정합니다.

## 5차 로컬 DXF 분석

- 서버나 유료 API 없이 브라우저에서 ASCII DXF 직접 분석
- HEADER 단위, ENTITIES, LINE, POLYLINE, LWPOLYLINE, INSERT, TEXT, MTEXT, CIRCLE, ARC 추출
- CAD 전체 경계를 Canvas 크기로 자동 정규화
- 설비 후보를 바로 배치하지 않고 승인·제외 검수 후 반영
- DWG는 AutoCAD 2013 ASCII DXF로 저장한 뒤 업로드

ES 모듈을 사용하므로 로컬 웹 서버에서 실행해야 합니다. `npm test`로 엔진과 데이터 모델을 검증할 수 있습니다.

## 최종 목표를 위한 확장 순서

1. 시뮬레이션 엔진, 화면 렌더러, 데이터 모델 분리
2. 레이아웃 프로젝트 JSON 스키마 정의
3. 도면 이미지 업로드와 캔버스 배경 표시
4. 컨베이어·로봇·스테이션 후보 자동 인식
5. 사용자가 인식 결과를 이동·수정·연결하는 편집기
6. 확정된 레이아웃 JSON으로 시뮬레이션 화면 자동 생성

자동 인식 결과는 바로 확정하지 않고, 신뢰도와 함께 후보로 표시한 뒤 사용자가 보정하는 흐름을 기본 원칙으로 합니다.
