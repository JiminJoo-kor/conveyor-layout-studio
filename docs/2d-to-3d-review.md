# 2D → 2.5D → 3D 개발 검토 및 승인 기준

검토일: 2026-10-30. 이 문서는 소스 구조와 자동 회귀 검사 기반의 1차 검토입니다. 모든 사용자 도면·모든 설비 조합·장시간 운전을 검증했다는 뜻이 아닙니다.

## 현재 상단 기능의 실제 역할

| 항목 | 현재 구현 | 주의 사항 |
|---|---|---|
| 설계 | 캔버스, 배치·연결, 파라메터 편집으로 이동 | 전용 모드나 일괄 편집 잠금이 아님 |
| 시뮬레이션 | 운영 패널로 이동. 고정 시간 스텝 엔진과 재생 제어 | 화면 재생 속도와 실제 시뮬레이션 시간을 분리 |
| 분석 | 생산성·CT·WIP·병목·구동·이벤트·자동 변경 로그 | 실측 KPI, 명목 CT, What-if 추정치를 구분 |
| 3D LIVE | AS/RS 작업 모니터 | 공장 전체 3D/물리 충돌 모델이 아님 |
| Split | 2D와 AS/RS 모니터 동시 표시 | 2.5D 레이아웃 구현이 아님 |

## 확인된 2D 문제와 이번 처리

| 우선 | 근거 | 영향 | 상태 |
|---|---|---|---|
| P1 | renderer.js의 monotonicVisualProgress가 token._visualProgress를 기록 | 화면/선택 계산이 엔진 물류 데이터에 부수효과 발생 | WeakMap 표시 캐시로 분리. 동결 토큰 테스트 추가 |
| P1 | editor.js의 선택 판정은 42px 반경, 실제 컨베이어/내부 스테이션은 다른 치수 | 빈 영역 선택, 긴 내부 스테이션 끝부분 선택 실패 | CAD 선택 범위를 공통 equipmentClipBounds와 일치시키고 6px 여유 적용 |
| P1 | app.js의 cadViewToggle이 item.x/y와 내부 스테이션 위치를 직접 변경 | 보기 전환이 모델 좌표에 영향. 3D에서 별도 좌표가 생기면 불일치 위험 | 구조 분리 필요. 이번에 전면 변경하지 않음 |
| P2 | 분석 탭이 이벤트 상태이면 simulationReport가 숨겨짐 | 상단 분석 이동 대상이 안 보일 수 있음 | 숨겨진 경우 생산성 분석으로 전환 후 이동 |
| P2 | 3D LIVE 명칭의 범위가 불분명 | 전체 3D로 오해 | AS/RS 3D LIVE로 범위 표시 |
| P2 | 검증 결과가 여러 패널로 분산 | 치수·연결·물류 소유 오류를 한 번에 파악하기 어려움 | 읽기 전용 레이아웃 점검 패널 추가. 실제 충돌 검증과 구분 |

## 기능별 구체화 로직 검토표

| 영역 / 주요 모듈 | 유지해야 할 규칙 | 추가 검증 / 남은 작업 |
|---|---|---|
| CAD / cad-import, dxf | 단위 확정 후 실제 길이 산출. 추정 연결은 승인 필요 | 곡선·외부 참조·전개 한도·다업체 도면 회귀. 블록 패턴은 종류만 기억하며 연결 패턴 학습은 미구현 |
| 배치 / editor, route | 설비 ID와 포트 ID가 연결의 기준. 선 교차는 연결 아님 | 설비 회전·이동·방향 변경·삭제 우회 후 연결 방향과 예약 검증 |
| 컨베이어 / engine, occupancy, kinematics | 진행축에 투영한 물류 길이 + 안전간격, 수신 승인 전 소유권 유지 | 다른 길이/회전/크기, 경계 걸침, 급정지, 연속 전달 조합 장시간 검증 |
| AMR·AGV / engine, renderer | 이동·복귀·수신·인계를 분리, 경로 및 시간 일치 | 배치 충돌과 실제 차체 충돌 구분, 다중 차량 충돌 회피는 별도 검증 필요 |
| 포킹·디버터 / engine, diverter | 가용 물류와 하류 승인 조건에 따라 분기. 비율 때문에 빈 상류를 무기한 기다리지 않음 | 다중 합류·연속 분기·예약 취소·반대 방향 인계 조합 검사 |
| AS/RS·서열렉 / asrs-*, sequence-* | 스태커별 독립 작업, 셀/운반/스테이션 재고 일치, 인계 완료 후 소유권 변경 | N개 인출·부분 재고·출구 걸침·출구 막힘 중 입고 공정 조합 검증 |
| 적재·분배 / stack-* | 묶음 ID와 개별 박스 수량 보존. 스토퍼·들어올림·내림·배출 단계 분리 | 혼합 크기·수량 부족·취소/초기화 시 수량 보존 검사 |
| 파라메터 / parameter-*, engineering-* | INPUT/AUTO/RESULT/STATUS 구분, mm UI와 m 엔진 변환, 승인한 설계값만 적용 | 실행 중 구조 변경과 운전값 변경의 공통 정책 필요 |
| KPI / report, history-memory | 실측/명목/추정 표시, 기간·분모·묶음/개별 수량 일관성 | 1×/고배속 동일 엔진 시간 대조, 기록 절삭 이후 누계 대조 |
| 렌더링 / renderer, cargo-detail, asrs-monitor | 동일 엔진 상태·시간을 읽기만 함. 표식/확대는 실제 점유와 분리 | 공통 장면 스냅샷과 공간 변환 계층으로 통합 필요 |
| 성능 / playback-budget, history-memory | 과거 프레임 무제한 저장 금지, 패널 비활성 갱신 중지 | 실제 대형 도면/장시간 브라우저 메모리 및 3D GPU 메모리 측정 필요 |

## 1단계 — 2D 안정화

1. 설계 모델(실제 치수·포트·연결), 엔진 실행 상태, 화면 배치/카메라를 분리한다. 기존 JSON의 x/y는 우선 화면 배치로 유지하고 실제 공간 좌표로 임의 해석하지 않는다.
2. 읽기 전용 장면 스냅샷을 도입한다: simulationTime, equipmentId, cargoId, ownerId, phase, progress, orientation, actualDimensions, visiblePose. 인계 중 양단 표현은 같은 cargoId의 표시 조각이지 두 개의 재고가 아니다.
3. 일반 컨베이어·내부 스테이션·차량의 그리기/선택/연결점 좌표를 같은 변환에서 산출한다.
4. 구조 편집은 일시정지 및 재초기화 정책을 명확히 하고, 분석은 그 실행 조건의 스냅샷을 참조한다.

완료 조건: 동일 JSON·동일 투입 조건·동일 엔진 시간에서 보기/확대/패널 개수와 관계없이 완료 수량·셀 재고·물류 소유·핸드셰이크 결과가 같아야 한다. 0/90/180/270도·길이가 큰 설비·상하류 정지·합류/분기 회귀가 필요하다.

## 2단계 — 2.5D

- 위 스냅샷을 등각 투영한다. 엔진을 하나 더 만들지 않는다.
- 설치 높이, 설비 외형 높이, 물류 높이, 적층 높이, 스태커 Z축을 별도로 정의한다. 모르는 높이는 예시값임을 표시한다.
- 가림 순서와 선택 역변환, 층별 필터, 연결점 높이 차를 구현한다.
- 물리 충돌은 원래 크기 기준이며 가시성 마커 크기로 계산하지 않는다.

완료 조건: 2D/2.5D 동시 표시에서도 ID·위치 기준·소유·재고·인계 진행률이 일치. 투영만 다르고 시퀀스/KPI는 같아야 한다.

## 3단계 — 전체 3D

- 같은 스냅샷에 3D 외형, 카메라, 조명, 층/높이, 부품 모션을 연결한다.
- 반복 박스/랙은 인스턴싱, 시야 밖 객체 생략, 텍스처·메시 해제, 단계별 품질 옵션을 적용한다.
- 모델 외형 간섭과 안전거리 검증을 추가하되 시뮬레이터 결과를 실제 설비 안전 인증으로 표현하지 않는다.

완료 조건: 2D/2.5D/3D의 동시간 상태 대조, 장시간 CPU/RAM/GPU 측정, 프로젝트 교체·초기화 후 리소스 회수 검사. 이 단계는 아직 구현 완료가 아니다.

## 이번 작업의 한계

공장 전체 2.5D/3D를 추가하지 않았으며 모든 시퀀스 조합에 대한 검증도 끝나지 않았습니다. 이번 변경은 2D의 확인된 문제를 고치고, 사용자에게 현재 기능의 범위와 점검 결과를 드러내는 첫 단계입니다. 큰 좌표 분리 작업은 기존 JSON 호환 및 운전 결과 동등성 검증과 함께 진행해야 합니다.
